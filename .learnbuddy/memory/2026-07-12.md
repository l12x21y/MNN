
## 理解 GazeFollower 代码架构 (2026-07-12)
- 定位：基于普通 webcam 的深度学习视线追踪系统（appearance-based），无需红外硬件；MGazeNet 多输入 CNN 经 MNN 推理。论文 PACM CGIT 2025。
- 设计模式：门面(GazeFollower) + 策略插件(5组件=抽象基类+默认实现, 构造注入) + 观察者(add_subscriber/dispatch) + 状态机(CameraRunningState 四态互斥)。
- 五大组件：Camera(WebCamCamera/OpenCV多线程), FaceAlignment(MediaPipeFaceAlignment), GazeEstimator(MGazeNetGazeEstimator, 输入 face+左右眼+rect), Calibration(SVRCalibration), Filter(HeuristicFilter)。可替换为 BlazeFaceAlignment/PolyCalibration/OneEuroFilter/PupilioCamera。
- 运行时：WebCamCamera 守护线程抓帧 -> process_frame 回调；按 PREVIEWING/SAMPLING/CALIBRATING 分支；SAMPLING 流水线 FaceAlign->GazeEst->Calibrate.predict->Filter->dispatch->写CSV。共享对象 FaceInfo/GazeInfo。
- 校准：CalibrationController 维护 5/9/13 点序列，每点收约45帧，眨眼过滤(眼开度阈值)，calibrate 拟合，convert_to_pixel 支持物理cm映射(cm2px/px2cm)。
- 支撑：misc(DefaultConfig/Enumeration/clip_patch/px2cm/generate_points/Recorder/TriggerHandler), ui(双后端 pygame/psychopy), logger。
- 落盘：临时CSV在 ~/GazeFollower/tmp，save_data 拷贝；列含 raw/calibrated/filtered 坐标+眼开度+状态+event+trigger。
- 依赖：mediapipe, MNN, numpy, opencv, pandas, pygame, screeninfo；模型 .mnn 格式(base 700万图, 另有3200万图需申请)。
- 待实现(TODO)：眨眼检测、事件检测(event枚举未真正分类)、校准优化、降抖。

## 人脸对齐 GPU 切换决策 (2026-07-12)
- 用户问"人脸对齐能否跑GPU"并给出条件："剔除眨眼帧影响大→别切GPU,维持当前状态"。
- 代码核查结论：眨眼剔除仅在**校准阶段**生效(CalibrationController 用 left/right_eye_openness>10 过滤眨眼帧, 保护 SVR 校准质量); 实时采样阶段 MGazeNetGazeEstimator 只记录眼开度、不据此剔帧。故眨眼剔除影响=大但范围在校准精度, 不导致卡顿/崩溃。
- 决策：**不切 GPU, 维持 MediaPipeFaceAlignment 默认(睁眼度检测最准)**。已从 GazeFollower.py 移除本次新增的 BlazeFaceAlignment 导入, 还原更接近"当前状态"。
- 卡顿治理改用与后端无关的**摄像头推理限速**：WebCamCamera.__init__ 新增 process_fps=15, capture() 内按 1/process_fps 最小间隔跳过中间帧(仅跳过预处理+回调, 仍每循环读取最新帧不积压), 把脸检测/眼动从~30Hz降到~15Hz, 释放CPU给视频解码/显示。CSV采样率同降为~15Hz, 不影响校准(每点仍够样本)也不碰眨眼剔除。
- 注：BlazeFaceAlignment.py 仍保留此次改好的 GPU(Vulkan/CPU回退)+真实眼开度代理代码, 但因不再被导入而处于休眠态, 可作未来可选GPU路径; 若用户要彻底还原可单独回退该文件。
