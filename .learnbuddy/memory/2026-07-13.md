## 第二次: 修复"最开始定位就崩溃" (calibration 崩溃)

### 根因 (与 GPU/CPU 无关的真实 bug)
- `GazeFollower.process_frame` 的 CALIBRATING 拟合分支:
  `features = np.array(feature_vectors); n_point, n_frame, feature_dim = features.shape`
  当全程没收集到有效特征(摄像头没检测到人脸/推理失败)时, `feature_vectors` 为空,
  `np.array([]).shape == (0,)`, 解包成 3 个值直接 `ValueError`。
- 该异常被摄像头线程 `capture()` 的 try/except 吞掉 → `cali_model_fitted` 永远 False →
  主线程 `CalibrationUI.draw_cali_result` 的 `while not cali_model_fitted:` 死等 → 校准冻死/崩。

### 修复
1. `gazefollower/GazeFollower.py` process_frame 拟合块整体包 try/except: 任何失败标记
   `cali_available=False`, 但**无论如何都置 `cali_model_fitted=True`**, 让 UI 正常退出
   (显示 Calibration failed) 而非冻结。并在文件顶部加 `import traceback` (原文件缺此导入,
   否则 except 内 `traceback.format_exc()` 本身会 NameError)。
2. 按用户"GPU 不行就用 CPU"的授权, `demo.py` 切到 CPU: `USE_CPU=1, USE_GPU=0`
   (backend=0)。本机 OpenCL(2)/CUDA(5) 为伪 GPU, Vulkan(4) 自检过但真实推理不稳;
   CPU 稳定。视频流畅性由架构(独立推理线程 + process_fps 限速 + 零分配显示)保证, 不受影响。
   眨眼帧剔除(eye_blink_threshold)原样保留, 与后端无关。

### 验证
- 无头复现: 空特征 → cali_model_fitted=True/cali_available=False 不崩; 有效特征(9点x45帧)
  → cali_model_fitted=True/cali_available=True 正常拟合。两条路径均不再崩。
- `import demo` 成功, 当前后端 CPU(backend=0)。
- 临时探针脚本 (_repro*.py, _gpu_real_test.py, _smoke_test.py) 已清理。
